Evidence needed for each release check

Sources and coverage

Do we know the exact original version and all source scope?

  • Version, license and source identity recorded.
  • All participants, recordings and observation types inventoried; gaps are explicit.

Source meaning

Are clocks, sides, units, signs and frames supported by source evidence?

  • Every claimed mapping has source evidence.
  • Unknown timing, mass, anatomy and measurements remain explicit.

Representative pilot

Does an independently checked pilot support the planned mapping?

  • Known reference cases cover the changed behavior and relevant failure cases.
  • Actual persisted pilot values, identities and missingness match independently read sources.

Complete source comparison

Has the complete declared export been reconciled to its original sources?

  • All exported observations and claimed signals checked over their declared scope.
  • Every source observation has a converted, excluded, missing or failed disposition.

Quality and limitations

Do diagnostics and profiles describe what is known without hiding missing evidence?

  • One assessment records passed, failed, missing, unchecked and invalid results.
  • Any profile has justified population, task and observation applicability; source quality limitations remain visible.

Release review

Do exact artifacts, evidence and researcher-facing claims agree?

  • Full and filtered artifacts share source lineage and exclusions.
  • Immutable manifest, hashes, source comparison evidence and actual review decision reconciled.
  • Downloads and previews match the reviewed artifact or remain explicitly legacy/unreviewed.

  • The backlog is a reviewed snapshot. Check source receipts and resource conditions at execution time; never infer current memory or worker state from this page.

Leaving a handoff

  • Read this backlog, the task inputs and current evidence before starting. Chat history is supporting context, not the authoritative handoff.
  • Continue one ready task per agent session. Record its ID and start time, and update its state when the work changes.
  • Keep the full declared source scope. Splitting a task or publishing a limited artifact does not complete missing participants, recordings or signals.
  • A job definition or saved waiting status is not proof of a live process. Verify the exact process identity; preserve terminal receipts and plan a fresh reviewed attempt.
  • Use one numerical worker, low process and I/O priority, bounded reads and the existing admission limits. Coordinate native MATLAB work before launch.
  • Keep source files, prior outputs and frozen job inputs immutable. Changed sources or code require fresh bindings and a new output identity.
  • At handoff record changed files, exact checks and their coverage, output evidence, remaining questions, the next action and any condition needed to unblock it.
  • Move completed deliverables to review. Mark done only when every acceptance criterion is evidenced; synthetic tests, source hashes or queue completion alone do not approve a scientific conversion.
  • Independent source checks must avoid reusing the converter assumption being tested. Report a source mismatch or unresolved convention instead of fitting signs or ranges to make it pass.
  • Record excluded and unavailable observations or signals explicitly. No profile match means unchecked; do not tune ranges to obtain a target pass rate.
  • The release gate records the actual reviewer and exact artifact identity. Publishing data still follows the user-requested destination and workflow.
